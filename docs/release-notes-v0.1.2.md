# v0.1.2 · 修「创建项目没反应」，并补输入安全

## 修了什么

### 创建项目点了没反应（v0.1.1 的真实问题）

服务端日志证明请求根本没发出去——从头到尾没有一次 `POST /api/projects`，也没有 `name-available`；
但用 curl 走同样的流程，注册 200 → 名字检查 200 → **创建 201**，后端一切正常。

问题在 `create_project_page.dart`：

```dart
if (_nameError != null) return;   // 静默返回，按钮点了什么都不发生
```

只要名字预检查留下了错误状态，点「创建项目」就毫无反应。现在改成：

- 明确把原因显示出来，不再静默
- `_checkName` 里被吞掉的非网络异常也会显示（断网除外，交给提交时报错）
- 补充 `mounted` 保护，避免页面已退出时 setState

### 新增「关于」页

项目列表页右上角 → 关于。能看到：

- 版本号
- **服务器地址**（只读，release 包里改不了）
- 后端连通性 + 后端版本 + 往返延迟，可手动重新检测
- 设备 ID（长按可复制，报问题时提供这个即可定位）
- 协议与源码地址

以后连不上，先看这一页，不用再猜是网络还是配置。

### 界面

- **只保留浅色主题**：不再挂 `darkTheme`，系统切深色时 App 仍是浅色（工地强光下深色反而更难读，两套配色也是双倍走查成本）
- 底部导航从 4 项变 5 项：库存 / 匹配 / **录入** / 流水 / 项目。录入是动作不是常驻页，点它直接推表单，返回后自动刷新库存

## 后端输入安全（同版本部署）

| 问题 | 处理 |
| --- | --- |
| 项目名可存控制字符（`\x00`、`\x1b`）、不可见字符（零宽空格 U+200B、RTL 覆写 U+202E、BOM） | 拒绝 Unicode `Cc/Cf/Cs/Co/Cn`，报错时指出第几个字符和码位；**改名走同一套检查**（原本是绕过口子） |
| CSV 导出有「项目」「备注」两列且无公式转义，Excel 打开会执行 `=HYPERLINK(...)` | 新增 `_csv_safe`：以 `= + @ \t \r` 开头加前导 `'`；`-` 只在不像数字时加，避免写坏 `-5` |
| `name_key` 列宽 160，但名称允许 120 字符，NFKC 展开（`㍿`→`株式会社`）后可能撑爆，PostgreSQL 直接 500 | 入表前校验归一化长度，超了给明确提示 |

验证：`pytest` **124 passed**（新增 19 个用例）；公网实测 NUL 与零宽空格返回 422，正常名字 201。

## 现在能做什么

服务端：<https://www.z7ui.cn/tile-api>（`/healthz` 返回 `v0.1.2`）

App 里能完整走通：建项目 → 邀请码加入 → 录库存 → 匹配 → 切割（余料入库或丢弃）→ 溯源 → 导出 CSV。

## 已知限制

- debug 签名，自用没问题，长期分发前要生成 keystore
- AGP 仍是 8.5.2，靠 `--android-skip-build-dependency-validation` 在 Flutter 3.47.9 上打包
- 同名项目（含已软删除的）仍占用全局唯一，这是既定规则
